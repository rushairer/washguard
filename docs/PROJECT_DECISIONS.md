## 2026-09-27：建立项目事实源

- 核心仓库：`rushairer/washguard`
- 主分支：`main`
- 后续产品定义、实验设计、算法架构、开发计划和比赛材料，以主分支最新文档为主要事实源。

## 2026-09-27：首版硬件原型

首版验证硬件：

- EVAL-ADXL355Z
- XIAO ESP32S3
- SPI 连接
- USB 供电与数据导出优先

现阶段不急于制作定制 PCB、外壳、电池系统或无线产品化链路。

## 2026-09-27：第一阶段目标是“可观测性”，不是“训练模型”

第一台洗衣机的首批数据定位为 **Exploratory Dataset（探索性数据集）**。

第一阶段需要回答：

1. 外壳振动能否稳定观察到洗衣机运行变化？
2. 静止、低速运动、高速脱水、冲击等物理状态是否具有可区分特征？
3. 同一状态在不同时间是否具有基本一致性？
4. 哪些特征对安装位置和方向最敏感？
5. 哪些特征有希望跨位置、跨机型泛化？

第一台洗衣机的数据不能直接被视为“通用洗衣机模型”的训练集。

## 2026-09-27：不把固定洗衣流程作为底层假设

不同品牌、不同机型、不同程序的流程顺序和振动组合都可能不同。

因此底层算法不应硬编码：

`进水 → 洗涤 → 漂洗 → 脱水 → 完成`

更合理的做法是先识别可迁移的**运动原语（Motion Primitive）**，例如：

- 静止 / 极低振动；
- 微弱持续振动；
- 低速周期旋转；
- 正反转交替；
- 中速旋转；
- 高速稳定旋转；
- 加速 / 减速；
- 强冲击 / 非周期振动；
- 短暂停顿。

更高层再结合时序关系解释为洗涤、漂洗、脱水、完成或异常。

## 2026-09-27：跨安装位置适配策略

不依赖固定的 X/Y/Z 轴含义。

优先研究：

- 三轴合成动态能量；
- 去重力后的 RMS；
- 方差；
- 峰峰值；
- 峭度；
- Crest Factor；
- 主频；
- 频谱质心；
- 各频带能量占比；
- 频谱熵；
- 自相关与周期性。

同时通过设备自校准解决不同安装位置导致的绝对振幅变化。

## 2026-09-27：Machine Profile 是核心能力

每个 WashGuard 安装实例可以逐步形成自己的 Machine Profile，包括但不限于：

- 静止噪声基线；
- 振动幅度尺度；
- 共振频谱；
- 主导频率；
- 常见运动聚类；
- 状态置信度阈值；
- 历史周期统计。

目标不是让设备“记住某个型号”，而是让它逐渐认识自己当前安装的这台洗衣机。

## 2026-09-27：采用混合算法架构

规划路线：

```text
原始三轴振动
    ↓
DSP / 去重力 / 滤波 / 归一化
    ↓
Machine Profile 自校准
    ↓
统计与频域特征
    ↓
规则 / 阈值 + 后续可选 ML
    ↓
Motion Primitive
    ↓
时序 / 状态模型
    ↓
用户状态
```

机器学习不是第一阶段前提。

当跨机器、跨程序、跨位置的数据量足够后，再比较 Random Forest、XGBoost、SVM、轻量时序模型等方案是否真正优于可解释的 DSP + 状态机。

## 2026-09-27：产品价值分层

优先级从高到低：

1. Idle / Running / Finished
2. 低活动 / 洗涤类 / 高速脱水
3. 洗涤 / 漂洗 / 排水 / 脱水等更细状态
4. 偏载、撞桶、失衡、异常停止等异常识别

不以“一开始就精确识别所有厂商全部工序”为首版成功标准。


## 2026-09-27：原型机械结构与正式 PCB 路线

- V0.1 使用 EVAL-ADXL355Z + 3D 打印刚性绝缘底座，四点螺丝固定。
- 原型阶段允许 P1/P2 公排针朝上，通过短杜邦线连接 XIAO；这是调试接口，不是正式产品接口。
- EVAL-ADXL355Z 不作为量产产品永久组成部分。
- 正式版将 ADXL355 LGA 芯片直接回流焊到自研 Sensor PCB。
- 保留两种正式硬件候选：单 PCB 一体化，或 Sensor PCB + Main PCB 双板架构。
- 当前更重视传感器机械耦合和数据质量，不为了提前减少 PCB 数量而锁死架构。
- 自研 Sensor PCB 应尽量小、硬、轻，并复用原型阶段验证过的安装基准和方向。
