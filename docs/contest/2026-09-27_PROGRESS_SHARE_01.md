## 一、WashGuard 到底要解决什么问题

WashGuard 想做的是一个不改造洗衣机内部结构的外置状态监测器。

核心思路很简单：

把 ADXL355 高精度三轴加速度传感器固定在洗衣机外壳，通过机身振动判断洗衣机现在是静止、运行、脱水还是已经结束，未来进一步尝试识别偏载、异常撞击等情况。

理想中的使用方式是：

~~~text
洗衣机
  ↓ 机身振动
ADXL355
  ↓
ESP32-S3
  ↓
信号分析 / 状态判断
  ↓
运行状态、完成提醒、异常提醒
~~~

项目的 GitHub 仓库今天也已经初始化：

`https://github.com/rushairer/washguard`

仓库里的工程文档统一使用中文，后续重要实验结论也会持续整理进去。

## 二、第一阶段不急着上机器学习，先证明“振动能不能看懂”

这个项目最开始很容易产生一个想法：

“不同洗衣机流程不同，是不是直接用机器学习？”

后来仔细分析后，我决定暂时不这么做。

因为现在连第一份真实数据都还没有，如果直接把某一台洗衣机的数据标成“洗涤 / 漂洗 / 脱水”去训练，很容易得到一个只认识这一台机器、这一个安装位置的模型。

所以第一阶段要回答的其实更基础：

> ADXL355 固定在洗衣机外壳以后，不同工作状态的振动到底有没有稳定、可重复的差异？

因此第一轮只做真实数据采集。

计划使用：

- EVAL-ADXL355Z；
- XIAO ESP32S3；
- SPI 通信；
- USB-C 供电和串口数据传输；
- 电脑保存原始 CSV。

初始采样参数准备从 **500 Hz、±2 g、XYZ 三轴原始数据**开始。

## 三、先做一个 60 秒的小预检，再洗完整一锅

为了避免接错线以后直接浪费一个完整洗衣周期，我把实验拆成了两步。

第一步叫：

**WG-PREFLIGHT-001**

只采大约 60 秒。

传感器固定好后先静止一段时间，中间人工轻敲洗衣机机身几次，然后检查：

- 实际采样率是否接近 500 Hz；
- 有没有丢样；
- 时间戳是否连续；
- 有没有削顶；
- 轻敲时数据有没有明显响应。

这一步通过后，才开始：

**WG-EXP-001**

也就是第一台洗衣机的完整洗衣周期采集。

同时人工记录关键时刻，例如：

~~~text
启动
进水
低速洗涤
暂停
漂洗
高速脱水
完成
~~~

这些人工记录会作为 Ground Truth，后续与振动曲线对齐。

这也是目前我认为最重要的一件事：**先把数据采对，再讨论算法。**

## 四、不同洗衣机怎么适配？目前的思路是“先认识振动，再认识洗衣机”

不同品牌、波轮/滚筒、不同程序、不同安装位置，振动组合肯定都不一样。

所以目前没有计划把某一个固定流程写死成：

“洗涤 → 漂洗 → 脱水 → 完成”。

更希望底层先识别一些物理上的运动模式，例如：

- 静止；
- 微弱持续振动；
- 低速周期运动；
- 正反转交替；
- 中高速旋转；
- 高速稳定旋转；
- 加速 / 减速；
- 非周期冲击。

然后每一台设备再逐步建立自己的 Machine Profile，例如静止噪声、振动尺度、常见频率和运行模式。

目前计划的算法路线大致是：

~~~text
XYZ 原始振动
    ↓
滤波 / 去重力 / 归一化
    ↓
设备自校准 Machine Profile
    ↓
RMS / 频谱 / 周期性等特征
    ↓
Motion Primitive
    ↓
状态机 / 时序推断
    ↓
Idle / Running / Finished / Spin / Abnormal
~~~

机器学习后面可以加，但它不是项目起步的前提。

## 五、给 ADXL355 先设计一个真正能测振动的底座

EVAL-ADXL355Z 本身很小，而且有四个安装孔，我准备直接利用这四个孔做一个 3D 打印绝缘底座。

结构目标不是“好看”，而是：

- 绝缘；
- 尽量刚性；
- 四点螺丝固定；
- 不让 PCB 背面直接碰洗衣机金属；
- 杜邦线不能直接拉扯传感器板；
- 尽量减少底座自身对振动的影响。

所以底座还增加了线缆应力释放结构。

今天主要是在 CAD 中反复修改立柱根部圆角、压线结构、线槽、倒角和 FDM 打印悬垂问题。

目前还只是 CAD 草模，**尚未打印验证**。

## 六、今天也提前想了一下将来的产品到底长什么样

这里有一个比较大的方向变化。

一开始考虑过正式产品重新做一块自己的 ADXL355 Sensor PCB。

后来觉得对于比赛版和早期产品没有必要为了“完全自研”增加额外风险。

目前更倾向于：

> **未来直接把 EVAL-ADXL355Z 当作正式 Sensor PCB。**

它本身已经足够小、足够硬，而且 ADXL355 周边电路都是现成验证过的。

未来产品可以做成一个扁平的小盒子，里面分两个区域：

~~~text
┌─────────────────────────────┐
│ Sensor Zone │ Main Zone     │
│             │               │
│ ADXL355     │ ESP32-S3      │
│ 评估板      │ USB-C         │
│             │ 蜂鸣器        │
│             │ 按键          │
└─────────────────────────────┘
~~~

两块 PCB 尽量侧向并排。

ADXL355 直接刚性固定到底壳；ESP32-S3 主控、电源、USB-C 和蜂鸣器放到另一边，减少主控板质量对传感器区域的影响。

这里特别说明一下：**目前方案没有 RGB 灯，提示硬件考虑蜂鸣器。**

原型阶段还会使用排针和杜邦线，正式产品则会换成更可靠的短线束或锁扣连接器。

所以现在还不能说“采集系统完成了”。
